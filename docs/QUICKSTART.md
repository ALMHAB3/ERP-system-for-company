# دليل البدء السريع والتجربة — شركة هب الريح لعوازل الأسطح ومواد البناء

## 1) التثبيت على جهازك (الخادم)
المطلوب: Docker Desktop (ويندوز/ماك) أو Docker Engine (لينكس).

```bash
./scripts/install.sh          # لينكس / ماك / WSL
```
```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1   # ويندوز
```
يسأل السكربت عن: اسم الدخول على الشبكة، بريد المدير الأول (ويطلب كلمة مرور)، وهل تريد **بيانات تجريبية** (الافتراضي: لا، فيبدأ النظام فارغاً جاهزاً للعمل الحقيقي؛ اختر نعم للتجربة فقط).
بعد الانتهاء افتح `https://erp.local` (أضف `127.0.0.1 erp.local` لملف hosts على هذا الجهاز، وعلى الأجهزة الأخرى عنوان الخادم). ثبّت الملف `caddy-root.crt` مرة واحدة في كل جهاز ليثق بالشهادة.

## أيقونة على سطح المكتب والهاتف
- **ويندوز:** `powershell -ExecutionPolicy Bypass -File launcher\Create-Shortcut.ps1` ينشئ أيقونة «Hub Alreeh ERP» على سطح المكتب: نقرة واحدة تشغّل Docker والنظام وتفتح الصفحة. `launcher\Stop-ERP.bat` للإيقاف (البيانات محفوظة).
- **لينكس/ماك:** `launcher/start-erp.sh`.
- **تطبيق مستقل (كروم/إيدج):** افتح النظام ثم زر «تثبيت» في شريط العنوان (أو ⋮ ← Cast, save and share ← Install page as app). يظهر بأيقونته في سطح المكتب بلا شريط متصفح. على الهاتف: «إضافة إلى الشاشة الرئيسية» (يتطلب الدخول عبر Tailscale أو شهادة موثوقة).

## 2) الدخول من أي مكان بخصوصية (Tailscale — بدون فتح منافذ)
1. ثبّت Tailscale على الخادم وعلى هاتفك/حاسوبك وسجّل بنفس الحساب.
2. على الخادم:
```bash
tailscale serve --bg --https=443 http://127.0.0.1:8080
```
3. افتح العنوان الذي يعرضه الأمر (`https://<اسم-الجهاز>.<tailnet>.ts.net`) من أي جهاز عليه Tailscale. الشهادة صالحة تلقائياً.
(للنشر العام بدومين: `docs/INTERNET-ACCESS.md`.)

## 3) الحسابات والصلاحيات
- **حسابك (مدير النظام):** الحساب الذي أنشأته أثناء التثبيت. هو الوحيد الذي يضيف المستخدمين والفروع (المستخدمون والتدقيق ← المستخدمون / الفروع والمستودعات). **مدير النظام والمدير العام لا يبيعان:** البيع لمندوب المبيعات فقط، والمدير يرى المبيعات (اليوم / آخر 7 أيام / آخر 30 يوماً) حسب المندوب وطريقة الدفع.
- الأدوار: مدير النظام، المدير العام، المدير المالي، المحاسب، مدير الموارد البشرية، مدير المشتريات، أمين المخزن/عامل، مندوب مبيعات. 
- **حسابات التجربة** (كلمة المرور لكلها `Demo-Passw0rd-123`): manager@ (مدير عام) / finance@ / accountant@ / hr@ / purchasing@ / warehouse@ / sales@ `demo.test`. يظهر شريط «بيانات تجريبية» في أعلى الشاشة.

### الفروع وموظفوها
- **أدوار الفروع** (تُعطى مع تحديد الفرع، ولا ترى إلا بيانات فرعها):
  - **مدير الفرع:** مبيعات الفرع ومخزونه وتحصيلاته وحساباته وموظفوه (اطلاع)، واعتماد البيع تحت هامش الربح.
  - **محاسب الفرع:** فواتير الفرع وديون عملائه وتحصيلاته وصندوقه، وميزان مراجعة الفرع وأرباحه.
  - **موارد بشرية للفرع:** موظفو الفرع وحضورهم وإجازاتهم وعقودهم، ورواتبهم (اطلاع).
  - **البائع (مندوب مبيعات)** و**أمين المخزن** يُربطان بفرعهما كما كان.
- **محاسب الشركة** (المحاسب / المدير المالي) يرى كل الفروع، ويستطيع اختيار فرع في ميزان المراجعة وكشف الحساب.
- كل قيد محاسبي يحمل فرعه: المحاسبة ← **أرباح الفروع** تعرض مبيعات كل فرع وتكلفته ورواتبه وصافي ربحه، و«الصندوق والحسابات المصرفية» يعرض رصيد صندوق كل فرع.
- الشاشات التي تخص الشركة كلها (الموردون، الاستيراد، الحسابات المصرفية، التسوية البنكية، تقييم العملة) لا تظهر لموظفي الفروع. كشوف الرواتب تُنشأ وتُعتمد مركزياً، وتُقسَّم قيودها على الفروع تلقائياً.

## 4) سيناريوهات تجربة مقترحة
- **البيع (بحساب sales@demo.test):** المبيعات ← بيع جديد: شاشة كالفاتورة، جدول (الرقم، كود الصنف، اسم الصنف، العدد، سعر القطعة، المجموع) ثم إجمالي الفاتورة، وتحته شريط: طريقة الدفع (نقداً / تحويل مصرفي مع المصرف / دين على العميل) والمدفوع والخصم %. اكتب الكود أو الاسم + Enter ثم الكمية + Enter للسطر التالي. اسم الزبون اختياري («غير معروف» إن تُرك). «إتمام البيع» يصدر الفاتورة في خطوة واحدة. إن دفع أقل من الإجمالي يبقى الباقي ديناً على عميل مسجَّل. الخصم لا يتجاوز الحد الأدنى للهامش. الدين مرفوض لغير العملاء المسجَّلين (سجّل العميل من شاشة «العملاء»).
- **المدير:** بحساب manager@ افتح «المبيعات» وبدّل بين اليوم / 7 أيام / 30 يوماً. لاحظ أنه لا يملك «بيع جديد».
- **العملاء والديون:** تحصيل الديون، والديون المطلوبة من العملاء (أعمار الديون). **الموردون:** فواتير الموردين، الدفع، الديون المطلوبة للموردين. **المشتريات:** أوامر الشراء، المطابقة، التكلفة النهائية.
- **الشحنة:** الاستيراد ← شحنة جديدة: لكل صنف أدخل سعر الشراء **وسعر البيع**؛ يُعتمد سعر البيع تلقائياً عند الاستلام. حقل تاريخ الصلاحية يظهر فقط للأصناف المحدَّد أنها «لها تاريخ صلاحية» (عند إضافة الصنف).
- **الموارد البشرية (بحساب hr@demo.test):** الموظفون (إضافة وتعديل وإنهاء خدمة)، الحضور اليومي (الغياب يُخصم: الراتب ÷ 30 لكل يوم)، الإجازات (بدون راتب تُخصم)، السلف (تُخصم أقساطها تلقائياً)، الرواتب: عند إضافة الموظف حدّد **علاوته الشهرية الثابتة** (أو اتركها فارغة)؛ وتُضاف تلقائياً كل شهر. أضف أي علاوات/مكافآت/خصومات إضافية للشهر ثم «إنشاء كشف الرواتب» ← «اعتماد» (يُسجَّل المصروف في الحسابات) ← يدفعها المدير المالي (بحساب finance@) من الصندوق أو مصرف. كشف الراتب لكل موظف قابل للطباعة.
- **الفروع:** (مدير النظام) أضف فرعاً ثم أعطِ المستخدمين صلاحية العمل فيه.
- **الفاتورة الإلكترونية:** «عرض الفاتورة» (QR وبصمة) أو XML، و`docker compose exec app php artisan invoices:verify`.
- **التكاملات:** ويب هوك وتصدير CSV (مدير النظام) — راجع `docs/INTEGRATIONS.md`.
- **السلامة:** `docker compose exec app php artisan inventory:reconcile` و `audit:verify` (يجب أن ينجحا).

## 5) الانتقال للعمل الحقيقي (حذف البيانات التجريبية)
على جهاز الخادم، من مجلد المشروع:
```bash
./scripts/go-live.sh                                            # لينكس / ماك
```
```powershell
powershell -ExecutionPolicy Bypass -File scripts\go-live.ps1   # ويندوز
```
1. يأخذ **نسخة احتياطية** من القاعدة الحالية إلى `./backups`.
2. يطلب كتابة `RESET` ثم يحذف **كل** السجلات: الأصناف والمخزون والشحنات والمبيعات والفواتير والدفعات والعملاء والموردين والموظفين والرواتب والقيود وحسابات التجربة (`@demo.test`) وسجل التدقيق، ويختفي شريط «بيانات تجريبية».
3. **يُبقي حساب المدير** بنفس البريد وكلمة المرور، ويعيد البيانات الأساسية (دليل الحسابات، العملات، الأدوار، العميل النقدي). شهادة الشبكة لا تتغير.

يرفض الأمر العمل على نظام لم تُحمَّل فيه بيانات تجريبية (حماية للبيانات الحقيقية).
بعد الدخول بحساب المدير تظهر في لوحة المؤشرات قائمة **«تجهيز المنظومة للعمل»**: بيانات الشركة، الفروع، المستخدمون، أسعار الصرف، الحسابات المصرفية، الأصناف، العملاء، الموردون، الموظفون. تختفي القائمة عند اكتمالها.

## 6) ما لم يُختبر/لم يُبنَ بعد
- ملفات Docker لم تُشغَّل في بيئة التطوير (صُدِّق على Caddyfile وبنية السكربتات فقط): أبلغني بأي خطأ في أول تشغيل.
- لم يُبنَ: المصادقة الثنائية (مُوصى بها قبل أي نشر عام). الفوترة الإلكترونية عامة وغير معتمدة من جهة ضريبية (انظر INTEGRATIONS.md).
- منطق التكلفة النهائية وفروق العملة يحتاج مراجعة محاسب قانوني قبل الاعتماد.
