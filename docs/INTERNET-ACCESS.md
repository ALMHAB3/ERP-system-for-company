# الوصول من الإنترنت (وجهازك هو السيرفر)

النظام يعمل على جهازك ويُفتح بثلاث طرق، ويمكن الجمع بينها:

| الطريقة | من يصل | ما تفتحه في الراوتر | الأنسب |
|---|---|---|---|
| **1. الشبكة المحلية (الافتراضي)** | الأجهزة داخل المقر | لا شيء | الموظفون في المقر |
| **2. Tailscale (شبكة خاصة)** | أجهزتك وأجهزة موظفيك المسجَّلة فقط | لا شيء | **الأكثر أماناً** للمدير والفروع: النظام لا يظهر للإنترنت أصلاً |
| **3. نفق Cloudflare** | أي شخص لديه الرابط (ويمكن حصره بتسجيل دخول) | لا شيء (اتصال صادر فقط) | موظفون ومندوبون خارج المقر برابط عام |
| **4. دومين مباشر على جهازك** | أي شخص | فتح المنفذين 80 و443 | يلزمه IP عام حقيقي (لا يعمل خلف CGNAT) |

**توصيتي:** 1 للمقر، و**2 (Tailscale)** للإدارة، و**3 (النفق)** فقط إذا احتجت وصولاً عاماً للمندوبين. تجنّب 4 ما لم تعرف إدارة الراوتر والجدار الناري.

## شروط لا بدّ منها لأن جهازك هو السيرفر
- **يجب أن يبقى الجهاز شغّالاً** ومتصلاً بالإنترنت عند الحاجة: عطّل السكون (Sleep)، واجعل Docker يبدأ مع النظام، ويُفضَّل UPS.
- **Windows:** ثبّت Docker Desktop مع WSL2، وفعّل «Start Docker Desktop when you sign in»، واجعل الجهاز يعيد التشغيل تلقائياً بعد انقطاع الكهرباء (من BIOS).
- **النسخ الاحتياطي** (انظر `LOCAL-DEPLOYMENT.md`) إلى قرص آخر/جهاز آخر؛ جهاز واحد يعطب = ضياع كل شيء.
- ثبّت تحديثات النظام (Windows/Linux) و`docker compose pull` شهرياً.

## الطريقة 2: Tailscale (الأسهل والأأمن)
1. ثبّت Tailscale على جهاز السيرفر وعلى كل جهاز يحتاج الوصول (الهاتف والحاسوب) وسجّل الدخول بالحساب نفسه.
2. من لوحة Tailscale فعّل MagicDNS وانسخ اسم جهاز السيرفر (مثل `office-pc.tailnet-name.ts.net`).
3. في `.env`: `ERP_HOST=office-pc.tailnet-name.ts.net` ثم `docker compose up -d`.
4. افتح `https://office-pc.tailnet-name.ts.net` من أي جهاز مسجَّل (ثبّت شهادة Caddy الداخلية مرة واحدة كما في دليل المقر، أو استخدم `tailscale cert` للحصول على شهادة موثوقة).
   لا يصل إليه أحد خارج شبكتك الخاصة.

## الطريقة 3: نفق Cloudflare (رابط عام بلا فتح منافذ)
1. تحتاج دومين (أو نطاق فرعي) مُضافاً إلى حساب Cloudflare مجاني.
2. في Cloudflare Zero Trust: Networks → Tunnels → Create → اختر Docker → انسخ الـ**token**. اجعل الوجهة العامة (Public hostname) `erp.شركتك.com` إلى الخدمة `http://web:8081`.
3. في `.env`: `TUNNEL_TOKEN=...` ثم:
   ```bash
   docker compose --profile tunnel up -d
   ```
4. افتح `https://erp.شركتك.com`. شهادة HTTPS من Cloudflare، ولا منفذ مفتوح عندك.
5. **أضف طبقة حماية** من Zero Trust → Access → Applications: اشترط تسجيل دخول ببريد الشركة (رمز لمرة واحدة) قبل أن تصل الصفحة إلى النظام أصلاً. هذا يقلل مخاطر الاختراق كثيراً.
- مدخل النفق (المنفذ 8081) غير منشور على جهازك ولا يراه إلا حاوية `tunnel`، وهو الوحيد الذي يثق بعنوان العميل الذي يرسله Cloudflare، فيسجّل سجل التدقيق عنوان IP الحقيقي للمستخدم.

## الطريقة 4: دومين مباشر على جهازك (متقدم)
1. دومين يشير إلى IP عامك (استخدم DDNS إن كان متغيراً)، وفتح 80 و443 في الراوتر نحو الجهاز.
2. `.env`: `CADDYFILE=./docker/Caddyfile.public` و`ERP_HOST=erp.شركتك.com` و`ACME_EMAIL=بريدك`. يحصل Caddy على شهادة Let's Encrypt ويجددها تلقائياً.
3. هنا يصبح النظام ظاهراً لكل الإنترنت: طبّق قائمة الأمان أدناه كاملة، وفكّر في إضافة Cloudflare أمامه.

## قائمة الأمان قبل الفتح للإنترنت
- [ ] كلمات مرور طويلة وفريدة لكل مستخدم (النظام يشترط 12 حرفاً + أنواع)، وحساب المدير بلا اسم افتراضي.
- [ ] لكل موظف حسابه ودوره الأدنى المطلوب ومستودعاته فقط؛ أوقف الحسابات المنتهية فوراً (يُنهي جلساتها).
- [ ] `APP_ENV=production` و`APP_DEBUG=false` و`APP_URL=https://...` في `.env`.
- [ ] قاعدة البيانات وRedis غير منشورين خارج Docker (هكذا هما فعلاً). لا تفتح 5432 ولا 6379.
- [ ] النسخ الاحتياطي اليومي يعمل واختُبر استرجاعه، وسجل التدقيق يُفحص (`audit:verify` مجدول).
- [ ] راجع «المستخدمون والتدقيق ← سجل التدقيق» دورياً بحثاً عن `auth.login_failed` المتكرر.
- [ ] **المصادقة الثنائية (2FA):** غير مبنية بعد. أوصي بها بشدة قبل أي فتح عام للنظام (يحمل بيانات مالية). حتى ذلك الحين استعمل Tailscale أو Cloudflare Access (فهما يضيفان طبقة تحقق قبل صفحة الدخول).
- [ ] مراجعة أمنية خارجية قبل الاعتماد على الفتح العام.

## ما يحميك أصلاً
تسجيل دخول محدود بالمحاولات (5/دقيقة)، رموز دخول تنتهي بعد 8 ساعات، صلاحيات حسب الدور ونطاق المستودع، سجل تدقيق لا يُعدَّل، ترويسات أمان وCSP صارمة، وHTTPS دائماً.
